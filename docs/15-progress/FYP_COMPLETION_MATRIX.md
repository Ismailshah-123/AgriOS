## Weighting rule
- 100 points. P0 functional requirements share 71, P1 share 8, cross-cutting quality items (security, tests/CI, UX/i18n, documentation) share 21.
- Within P0, the core contribution (CAAIE: image model, calibrated confidence, rejection, explanation, integration) gets the largest share (37), because CLAUDE.md names it the core and the "never cut" list protects dataset records, honest evaluation and uncertainty handling.
- Completion % reflects the acceptance criterion in PRODUCT_REQUIREMENTS.md, not effort spent.

## Status classes
V = implemented and verified (automated tests recorded passing) · U = implemented, unverified (code + tests exist, no recorded passing run including them, or no saved result) · P = partially implemented · N = not implemented.
